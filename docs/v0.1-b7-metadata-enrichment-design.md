# v0.1-b7 Metadata Enrichment 设计规格

> 状态：已确认进入设计阶段。本文是 v0.1-b7 的施工前规格，用于约束后续 TDD 实现计划。

## 目标

v0.1-b7 的目标是新增一个 **Metadata Enrichment Layer（元数据增强层）**，把现有的普通检索、客观 auto-tags、CLAP embedding 和语义标签候选整合成稳定、可解释、可人工修正的录入结果。

一句话目标：

> 输入 `library.json`、音频目录和可选 `embeddings.json`，输出 `library.enriched.json`，让每个样本具备可检索、可解释、可审查的增强元数据。

## 非目标

v0.1-b7 明确不做：

- 不引入 SQLite、PostgreSQL 或其他数据库。
- 不引入 FAISS、Chroma 等向量库。
- 不做 Web UI 或 TUI。
- 不训练自定义 ML 分类器。
- 不把 512 维 CLAP embedding 直接写入 `library.json`。
- 不删除现有 `semantic-search`、`hybrid-search`、`auto-tag` 命令。

这些能力留给 v0.1-b8 或 v0.2。

## 现有基础

当前仓库已经具备：

- `app.py index`：生成 schema v1 的 `library.json`。
- `app.py auto-tag`：基于 librosa 生成客观标签。
- `app.py compute-embeddings`：生成 CLAP `embeddings.json`。
- `app.py semantic-search`：基于 CLAP 做纯语义检索。
- `app.py hybrid-search`：规则过滤 + CLAP 重排序。
- `audio_metadata.schema`：已经有 `retrieval` 和 `model_outputs` 扩展字段。

v0.1-b7 的工作不是重写这些能力，而是把它们组织成录入流水线。

## 用户流程

### MVP 流程

```text
音频目录
  ↓
app.py index
  ↓
library.json
  ↓
app.py compute-embeddings
  ↓
embeddings.json
  ↓
app.py enrich
  ↓
library.enriched.json
  ↓
app.py search / app.py tag --auto（后续统一入口）
```

### 推荐命令形态

MVP 先实现 `app.py enrich`：

```bash
python app.py enrich \
  --input ./out/library.json \
  --audio-root ./audio \
  --embeddings ./out/embeddings.json \
  --output ./out/library.enriched.json \
  --semantic-tags \
  --vocabulary ./config/semantic_tags.json
```

后续再增加更友好的别名：

```bash
amm search --semantic "温暖的吉他"
amm tag --auto --dry-run
amm tag --auto --apply
```

## 设计原则

### 1. JSON 仍然是主存储

保持当前项目的 local-first、single-user、JSON storage 方向。v0.1-b7 只扩展 schema 字段，不引入数据库。

### 2. embedding 单独存储

`library.enriched.json` 只保存 embedding 的引用和状态，不保存 512 维向量。

原因：

- 避免 `library.json` 体积快速膨胀。
- 保持元数据可读、可审查。
- 后续迁移到 SQLite 或向量库时更容易。

### 3. 自动标签必须可解释

CLAP 不是自由生成标签的模型。v0.1-b7 使用受控 vocabulary 做相似度匹配：

```text
audio embedding vs predefined text prompts
```

只有超过阈值的候选才写入 `semantic_tags`。

### 4. 默认不破坏用户数据

- 默认不覆盖输出文件。
- 默认不修改输入 `library.json`。
- 写文件时先写 `.tmp`，再原子替换为目标文件。
- 自动标签写入前支持 dry-run。

## 数据结构

### `retrieval` 扩展

建议在 `retrieval` 中增加以下字段：

```json
{
  "tags": ["guitar", "warm"],
  "mood": null,
  "texture": null,
  "density": null,
  "role": null,
  "domain": null,
  "semantic_tags": ["warm guitar", "soft plucked string"],
  "embedding_ref": "embeddings.json#<record_id-or-path>",
  "embedding_model": "laion-audioclip-full-2022",
  "embedding_status": "ready"
}
```

`embedding_status` 取值：

| 状态 | 含义 |
| --- | --- |
| `ready` | 找到了可用 embedding |
| `missing` | 没有匹配到 embedding |
| `invalid` | embedding 存在但维度或格式不合法 |
| `not_requested` | 本次 enrich 未提供 embeddings |

### `model_outputs` 扩展

建议在 `model_outputs` 中增加：

```json
{
  "auto_tags": ["is_sustained", "is_bright"],
  "auto_tags_confidence": {
    "is_sustained": 0.82,
    "is_bright": 0.64
  },
  "semantic_tags": ["warm guitar", "acoustic string"],
  "semantic_tags_confidence": {
    "warm guitar": 0.71,
    "acoustic string": 0.68
  },
  "classifier_version": "v0.1-b7-enrichment",
  "classifier_type": "hybrid_metadata_enrichment"
}
```

说明：

- `retrieval.semantic_tags` 用于检索入口。
- `model_outputs.semantic_tags` 用于记录模型输出和置信度。
- 人工修正仍然通过 `review.overrides` 或后续 tag review 流程完成。

## Semantic Vocabulary

### 文件格式

默认 vocabulary 文件建议放在：

```text
config/semantic_tags.json
```

格式：

```json
{
  "version": "v0.1-b7-default",
  "prompts": [
    {
      "tag": "warm guitar",
      "category": "instrument_texture",
      "text": "warm guitar",
      "threshold": 0.25
    },
    {
      "tag": "dark ambient pad",
      "category": "role_texture",
      "text": "dark ambient pad",
      "threshold": 0.25
    }
  ]
}
```

### MVP 默认词表

MVP 默认词表只覆盖高价值、低歧义标签：

- 乐器：`guitar`、`piano`、`drums`、`bass`、`synth`、`vocal`、`strings`
- 角色：`drum loop`、`one shot`、`pad`、`lead`、`bass loop`、`transition`、`impact`
- 质感：`warm`、`bright`、`dark`、`soft`、`aggressive`、`distorted`、`clean`
- 组合 prompt：`warm guitar`、`dark pad`、`bright synth lead`、`energetic drum loop`

### 中文 query 支持

v0.1-b7 可以先支持一个轻量映射表：

```json
{
  "温暖": "warm",
  "吉他": "guitar",
  "黑暗": "dark",
  "鼓循环": "drum loop"
}
```

MVP 中中文映射作为 P1，不阻塞 `enrich` 主流程。

## 匹配策略

### library record 与 embedding 匹配

按优先级尝试：

1. `record.source.path` 与 `embedding.path` 完全匹配。
2. 两者归一化为绝对路径后匹配。
3. `record.source.file_name` 与 `Path(embedding.path).name` 匹配。
4. 若未来 embedding 文件包含 record id，则用 `record.id` 匹配。

匹配失败时不抛异常，写入：

```json
"embedding_status": "missing"
```

并在 summary 中统计。

### semantic tag 生成

流程：

```text
加载 vocabulary
  ↓
计算或读取 text embedding cache
  ↓
对每个 audio embedding 计算 cosine similarity
  ↓
按 tag threshold 过滤
  ↓
取 top N 写入 semantic_tags
```

MVP 默认：

- `top_n = 5`
- `default_threshold = 0.25`
- 每条记录最多写入 5 个 semantic tags

## CLI 行为

### `app.py enrich`

参数：

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `--input` | 是 | 输入 `library.json` |
| `--output` | 是 | 输出 `library.enriched.json` |
| `--audio-root` | 否 | 用于路径归一化 |
| `--embeddings` | 否 | CLAP embedding JSON |
| `--semantic-tags` | 否 | 启用 semantic tag 生成 |
| `--vocabulary` | 否 | semantic vocabulary JSON |
| `--threshold` | 否 | 全局默认阈值 |
| `--top-n` | 否 | 每条记录最多标签数 |
| `--dry-run` | 否 | 只输出 summary，不写文件 |
| `--force` | 否 | 允许覆盖已有输出 |
| `--verbose` | 否 | 输出匹配详情 |

### 输出 summary

命令结束时输出：

```text
Enrichment summary:
  records: 120
  embeddings ready: 115
  embeddings missing: 5
  semantic tags added: 87
  output: ./out/library.enriched.json
```

## 验收标准

v0.1-b7 完成时必须满足：

- `python app.py enrich --input ... --output ...` 可运行。
- 不提供 CLAP 依赖时，仍可完成非语义 enrich。
- 提供已有 `embeddings.json` 时，不需要重新计算音频 embedding。
- 输出 JSON 保留所有原始 record 字段。
- 输出 JSON 包含 embedding coverage 状态。
- semantic tags 来自受控 vocabulary，不自由生成。
- 新增测试通过，现有测试不回归。

## 风险与应对

### 风险 1：路径匹配不稳定

应对：封装独立 `match_embedding_for_record()`，并用测试覆盖 path、absolute path、filename 三种情况。

### 风险 2：CLAP CPU 太慢

应对：`enrich` 默认只读取已有 audio embeddings。semantic tag 阶段只需要 text embeddings，可用 mock 测试。真实大规模计算仍走 `compute-embeddings`。

### 风险 3：自动标签误导检索

应对：使用 threshold、top N、dry-run 和 confidence 字段。低置信度不写入最终 tags。

### 风险 4：污染人工标签

应对：自动标签写入 `model_outputs.semantic_tags` 和 `retrieval.semantic_tags`，不覆盖 `review.overrides`。人工标签优先级留给后续 review/tag 设计。
