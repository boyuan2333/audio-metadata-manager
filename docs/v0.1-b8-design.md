# v0.1-b8 设计文档：统一搜索 + 库报告

## 背景

v0.1-b5~b7 完成了底层能力（auto-tag、CLAP embedding、enrichment），但用户面对的是 4 个分散的搜索命令和一堆 JSON 文件，不知道库有什么、怎么搜。

**用户目标：**
1. 音色库整理 — 知道库里有什么、缺什么、怎么分类
2. 自然语言检索 — 一句话找到想要的音色，不管基于文件名还是音频内容

## 设计目标

两个命令解决两个问题：

```bash
# 搜索：一个入口，智能路由
python app.py search "暗的 loop 120bpm"
python app.py search "温暖的钢琴"
python app.py search "kick drum"

# 报告：一个命令，看清全貌
python app.py report
```

## Task 1: 统一搜索 — `app.py search`

### 现状问题

| 命令 | 用途 | 问题 |
|------|------|------|
| `search` | 文件名/标签过滤 | 只能精确匹配，不理解语义 |
| `semantic-search` | CLAP 语义搜索 | 需要单独 embeddings 文件 |
| `hybrid-search` | 规则+CLAP 混合 | 需要两个输入文件 |
| `nl-query` | 自然语言解析 | 只解析不搜索 |

用户不知道用哪个，每个命令参数不同。

### 设计方案

**一个 `search` 命令，自动判断搜索策略：**

```bash
python app.py search "暗的 loop 120bpm" \
  --library ./out/library.json \
  --embeddings ./out/embeddings.json \  # 可选，有就用 CLAP
  --top-k 10
```

**路由逻辑（三优先级）：**

```
输入文本
  │
  ├─ 有明确结构化条件？（BPM、时长、格式、loop/oneshot）
  │   → 规则过滤（精确，快）
  │   → 在过滤结果上做语义排序（如果有 embeddings）
  │
  ├─ 有描述性词汇？（"温暖的"、"暗的"、"明亮的"）
  │   → CLAP 语义搜索（理解语义）
  │   → 结合文件名关键词二次过滤
  │
  └─ 纯关键词？（"kick"、"piano"、"808"）
      → 文件名 + 标签关键词匹配（快、准）
      → 有 embeddings 时补充语义排序
```

**输出格式：**

```
🔍 搜索: "暗的 loop 120bpm"
📋 策略: 规则过滤 + 语义排序
🎯 匹配: 23/156 个文件

 #  | 分数 | 文件名                          | 时长   | BPM  | 标签
----|------|--------------------------------|--------|------|--------
 1  | 0.92 | dark_pad_loop_120bpm.wav       | 4.0s   | 120  | pad, loop, dark
 2  | 0.87 | ambient_drone_loop.wav         | 8.0s   | 120  | ambient, loop, dark
 3  | 0.81 | cinematic_tension_loop.wav     | 6.0s   | 120  | cinematic, loop
```

### 实现计划

| 子任务 | 文件 | 说明 |
|--------|------|------|
| T1.1 | `audio_metadata/search_router.py` | 路由逻辑：分析查询 → 选择策略 |
| T1.2 | `audio_metadata/unified_search.py` | 统一搜索执行器 |
| T1.3 | `search_cli.py` | 新 CLI 入口 |
| T1.4 | `app.py` | 注册 `search` 子命令 |
| T1.5 | `tests/test_unified_search.py` | 路由 + 搜索测试 |

**依赖：** 现有 `nl_query.py`（解析）、`hybrid_search.py`（混合搜索）、`clap_embed.py`（语义）

## Task 2: 库报告 — `app.py report`

### 设计方案

```bash
python app.py report --library ./out/library.json
# 可选：--embeddings ./out/embeddings.json（显示 embedding 覆盖率）
```

## Task 3: 搜索准确率提升（可选，T1 完成后评估）

| 优化项 | 预期提升 | 复杂度 |
|--------|----------|--------|
| embedding 去噪（跳过静音段） | +5% | 低 |
| 多维度融合权重调优 | +10% | 中 |
| 文件名相似度（编辑距离）辅助 | +5% | 低 |

**判断标准：** T1 完成后实际测试，如果用户觉得搜索结果够用就不做，不够用再优化。

## 不做的事

- ❌ Web UI — CLI 先用熟
- ❌ 数据库 — JSON 够用
- ❌ 文件重组/重命名 — 风险高，搜索做好再动
- ❌ Segment 级分析 — 后续版本

## 验收标准

```bash
# 1. 统一搜索能跑通
python app.py search "kick drum" --library ./out/library.json
python app.py search "暗的 120bpm loop" --library ./out/library.json --embeddings ./out/embeddings.json

# 2. 库报告能跑通
python app.py report --library ./out/library.json

# 3. 测试通过
pytest tests/test_unified_search.py tests/test_report.py -v

# 4. 不破坏现有功能
pytest tests/ -v
```
